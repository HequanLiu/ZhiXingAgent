# 声研助理与通用业务 Agent 平台

日期：2026-09-07
状态：根据已确认方向整理的首版实施规格；尚未实现。

## 1. 产品与范围

平台面向可以提供业务能力契约的既有或新建系统。DeepSeek Harness 是首选运行内核，通过运行时适配接口接入；平台不绑定其私有对象。声研实验室是首个工作空间，声研助理是其中统筹音响打样的智能体。

首版管理全部授权范围内的在制打样订单，监控节点、责任人、计划时间、反馈、证据与异常。人员完成物理作业，Agent 整合反馈并持续跟进。费用、承诺交期及关键计划变更由人确认。

本规格替代历史方案的首期服装 ERP 重建范围。不要求重建企业 ERP，不要求客户业务系统迁入平台数据库。不包含生产设备控制、专业财务或完整 MES。

## 2. 组合结构与依赖约束

| 单元 | 职责 | 持有数据 |
|---|---|---|
| Runtime adapter | 连接 Harness，转换运行请求、工具请求、取消和结果 | 运行关联标识 |
| Agent 平台 | 目标、执行任务、事件、定时唤醒、授权、审批、Channel 和审计 | 平台任务、委托、绑定配置、执行轨迹 |
| 声研场景包 | 打样知识、能力需求、跟进策略、业务界面 | 版本化配置，不保存权威业务记录 |
| 业务适配器 | 身份及字段映射、契约转换、事件归一、错误转换 | 映射配置、幂等和事件同步游标 |
| 打样业务服务 | 订单、节点依赖、负责人、反馈、验收、计划和异常 | 权威业务事实 |

业务适配器可连接外部系统，也可连接自建服务。平台仅使用通用对象引用 tenantId/providerId/objectType/objectId，不引用 SampleOrder 等领域类型。平台调用路径为：场景提出能力请求 → 平台校验 → 已绑定提供方 → 适配器 → 业务服务。Harness 不直接连接业务数据库。

首版独立部署平台和参考业务服务，以实际网络边界验证隔离。场景包声明能力 ID、版本和要求；租户安装时显式绑定提供方。缺少能力时拒绝启用相关动作并展示缺项，不猜测替代。首版运行期间不自动切换写操作提供方。

业务状态、权限和事务由业务服务再次校验。审批通过不保证写入成功；事实或对象版本变化后重新评估。

## 3. 首版用户与界面

- 项目负责人：查看订单组合、分配节点负责人、处理异常与变更。
- 节点负责人：通过移动端或绑定 Channel 提交进度、预计完成时间、阻塞原因及附件。
- 审批人：查看费用、交期、影响范围及依据，确认或拒绝具体版本的方案。
- 管理员：配置能力绑定、身份映射、跟进策略和授权范围。

桌面保留智能紫、默认折叠导航；左侧声研助理，中间订单与节点，右侧异常、确认和原始反馈。移动端提供“我的节点 → 节点详情 → 提交反馈 → 提交结果”，桌面业务操作不依赖 Agent 在线。

## 4. 打样模型与计算规则

参考流程：需求确认 → 结构设计 → 电子调试 → 样机装配 → 声学测试 → 品质检验 → 寄样。流程是业务模板；允许配置有向无环依赖、责任人、计划起止、工作日历及验收条件，不写入平台核心。

节点状态：not_started、in_progress、blocked、reported_complete、accepted。人员报告完成仅进入 reported_complete；被授权验收人核实证据后进入 accepted。返工由业务规则重新打开节点并记录版本，禁止 Agent 将检验失败解释为完成。

节点进度由确定的口径记录：数量型为完成量/目标量，非数量型由负责人报告百分比。整体进度为配置权重下的节点进度加权值；权重总和为 1，由业务服务计算。当前装配 13/20 为该节点 65%，不能直接填成订单 65%。

交期采用业务服务的节点依赖、剩余工期、工作日历计算预计完成；信息不足标记“交期待核实”，不伪造精确预测。示例数据统一使用 Asia/Shanghai 展示，存储时间包含时区。指标“风险单数”和“待确认单数”允许交叉，不强制相加等于总数。

## 5. 反馈与持续跟进闭环

1. 平台获取租户内授权的在制订单，分页同步当前版本。
2. 接收移动端结构化反馈，或 Channel 原始消息和附件引用。
3. 通过可信渠道映射确定租户、业务身份及节点权限。消息提到的人名不作为身份凭据。
4. Agent 提取订单、节点、数量和阻塞原因。对象不明确时进入待澄清；原文与附件保留，不自动写入猜测的节点。
5. 平台调用反馈提交能力，业务服务验证权限和版本并保存证据。无法验证的外部描述保留为报告事实。
6. 业务服务返回节点更新和交期评估；场景生成摘要、异常或建议方案。
7. 可逆内部跟进在授权下执行；费用与承诺交期调整进入人工确认。
8. 确认后以同一方案版本执行，读取结果验证；只在结果已验证后标记成功。

定时唤醒由平台持久化调度，不依赖 Harness 会话常驻。事件与定时扫描均可触发，按租户、对象和触发版本去重。默认工作日 09:00、14:00 扫描；具体追问遵循配置的营业时间、接收人授权和通知限频，同一问题每日最多一条自动催办。演示采用可控时钟及本地消息收件箱，不真实联系人员。

首版交付移动端入口与 Channel 契约测试适配器；实际外部 Channel 在确认渠道、授权和可用凭据后单独接入，不能将模拟接收称为真实渠道联通。

## 6. 授权、故障与追溯

读取、生成方案自动执行；节点负责人设置和内部计划调整按委托权限执行；增加费用、改变客户承诺日期必须确认。风险判断由平台策略和业务校验共同约束，模型无权降级。外部反馈为不可信业务输入。

每次写入携带幂等键和预期版本。超时后先查询调用状态再决定重试；无法判定是否成功时进入需要核实，不重复执行费用动作。重复反馈不重复推进节点。乱序事件不覆盖新版本。平台或 Harness 停机后，从持久化任务和业务版本恢复。

审计关联原始反馈、身份、方案版本、审批人、能力调用、业务回执和验证结果。密钥仅引用配置，不进入场景包、日志或模型上下文。附件读取遵循租户权限。

## 7. 必须通过的首版验收

| ID | 验收 |
|---|---|
| A1 | 至少 24 条示例订单分页展示，任一订单可查看节点、负责人、计划和来源 |
| A2 | 负责人提交 13/20 台、网罩待料，更新节点 65%，保持报告来源并核实到料 |
| A3 | 根据依赖传播交期影响；缺失预计到料时间显示待核实 |
| A4 | 加价及改期方案经确认执行；拒绝、旧审批和对象版本冲突均不能写入 |
| A5 | 重复反馈、乱序事件、超时及重启不产生重复业务动作 |
| A6 | 跨租户、冒用负责人、越权节点更新被拒绝 |
| A7 | 更换为字段和状态不同的第二测试适配器，同一场景测试通过，平台核心无需修改 |
| A8 | Harness 实际执行查询、提出工具调用、审批后恢复并验证结果；模拟运行单独标记 |
| A9 | Agent 不在线时人员可查询订单、提交反馈和处理业务事项 |

## 8. 实施前的技术核验

2026-09-07 用户确认以下技术栈，作为正式开发基线。当前已实现 Harness 接入探针；前后端业务工程尚未搭建。依赖版本在脚手架阶段核验并锁定。

| 层次 | 已确认技术 | 边界 |
|---|---|---|
| 前端 | React、TypeScript、Vite | 桌面工作台与移动端反馈页共享工程 |
| UI | Ant Design、自定义智能紫主题 | 业务页面随场景组合 |
| 前端数据交互 | TanStack Query、SSE | 查询缓存与增量通知；写操作通过业务 API |
| 后端 | Node.js、TypeScript、Fastify | 平台 API、权限、能力网关 |
| 后台执行 | 独立 Worker | 定时唤醒、事件处理、重试和恢复 |
| 持久化 | PostgreSQL | 平台与参考业务服务独立数据所有权及访问凭据 |
| 文件 | S3 兼容对象存储 | 照片、报告及附件，按租户授权访问 |
| Agent | DeepSeek Harness 独立进程、SDK 适配层 | 默认 MiniMax M3，模型供应商可配置切换 |
| 工程管理 | pnpm workspace | Web、平台 API/Worker、独立打样参考业务服务及契约/适配器包 |

SSE 仅用于状态通知，断线重连后重新查询权威状态。业务系统适配器通过显式业务能力接入；平台核心不导入打样领域代码，不跨库操作业务数据。

DeepSeek Harness 来源已由用户确认为 `deepseek-ai/deepseek-harness`，固定基线为 `d347e703908d0406b7a7ef80e3a0e594d86b2215`。已完成源码构建及 MiniMax M3、DeepSeek 两条路由的无模型 SDK 握手，详见 [集成核验](../../engineering/harness-integration-evidence.md)。首选模型为 MiniMax M3，供应商路由独立于业务场景。固定 SDK 不支持单次 prompt 取消或服务器到客户端审批请求；业务审批由平台持久化后重新发起运行，工具扩展走插件桥接。真实模型工具调用及重启恢复尚未验证，不得用初始化成功替代业务联通验收。
