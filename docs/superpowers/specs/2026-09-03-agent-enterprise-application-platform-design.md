# Agent 企业应用平台设计规格

日期：2026-09-03  
状态：已确认，待实施计划  
首个产品组合：Agent Platform + CRM 基础包 + ERP 应用套件 + 服装外贸行业包

## 1. 文档目的

本文定义一个基于 DeepSeek Harness 的 Agent 驱动企业应用平台。平台不以 ERP 为不可替换的中心，而把 ERP、CRM、MES、WMS、SRM 等系统建模为可独立安装、组合和演进的业务应用包。

首期完整重建新的平台与 ERP 产品，不以旧 ERP 作为运行依赖。旧系统只作为业务规则梳理和数据迁移来源。

## 2. 已确认的产品决策

1. 产品定位为“Agent 企业应用平台”，ERP 是首个应用套件。
2. 采用通用平台内核与可插拔业务应用、行业包的产品结构。
3. DeepSeek Harness 承载 Agent 运行能力，但不拥有企业业务数据或最终业务规则。
4. 首期采用 Agent 中枢加模块化业务内核，不采用多业务 Agent 微服务架构。
5. Agent 采用风险分级自治：低风险自主、中风险受控自主、高风险人工确认。
6. 首期完整重建，不在旧 ERP 上叠加 Agent 控制层。
7. 首个行业落地为服装外贸，覆盖客户需求到订单利润的贸易闭环。
8. 首期不建设 MES、工厂生产、工序、计件、设备、专业总账、税务申报和工资核算。
9. Web 桌面端为首期主终端，传统业务界面必须保留，Agent 关闭后关键业务仍可人工完成。

首期验收中出现的“示例 MES 应用包”只用于验证 SDK、能力注册和跨应用事件边界，是不可用于生产的合约探针，不代表首期交付 MES 业务功能。

## 3. 产品目标与非目标

### 3.1 产品目标

- 用户以业务目标而非菜单操作驱动日常工作。
- Agent 能主动发现事件、制订计划、调用业务能力、验证结果并持续推进任务。
- 企业能够清楚定义 Agent 可以做什么、在什么条件下做、何时必须停止并交给人。
- 新增 Agent+CRM、Agent+MES 等产品组合时，不修改 Agent Platform 核心。
- 所有自动动作可授权、可审计、可回放、可停止，并尽量可补偿。
- 业务应用拥有确定性的规则、状态机和事务边界，不把正确性寄托于模型输出。

### 3.2 非目标

- 不让模型直接访问或修改生产数据库。
- 不把聊天记录当作业务事实来源。
- 不用 Prompt 替代领域规则、权限、审批或会计约束。
- 不在首期拆分大量微服务或部署彼此竞争的业务 Agent。
- 不追求一次覆盖所有行业和所有企业管理模块。

## 4. 总体架构

平台采用四层结构：

```text
DeepSeek Harness
        ↓
Agent Platform
        ↓
Business Capability Protocol
        ↓
CRM / ERP / MES / WMS / SRM / 行业包
```

### 4.1 DeepSeek Harness

DeepSeek Harness 是可替换的 Agent Runtime，提供模型适配、会话、Agent 循环、工具调用、技能、沙箱、存储、调度、后台任务和执行轨迹等能力。

约束：

- Harness 不保存客户、订单、库存、生产订单等权威业务事实。
- Harness 私有对象不得进入业务应用的领域模型。
- 平台通过适配层接入 Harness，避免业务模块直接依赖其快速变化的内部 API。
- 会话和执行轨迹与业务主数据独立存储，允许未来替换 Harness 或模型供应商。

### 4.2 Agent Platform

Agent Platform 提供与具体业务系统无关的公共能力：

- Agent 会话、目标、计划、步骤、任务和后台调度
- 能力注册、发现、调用、版本选择和运行状态
- 身份、租户、组织、角色、数据范围和委托授权
- 风险策略、审批、预算、速率限制和紧急停止
- 事件订阅、跨应用编排、人工接管和结果验证
- 企业知识、用户偏好、执行经验和版本管理
- 动态 Surface 工作区、全局搜索、通知和审计轨迹

Agent Platform 不得引用 `Customer`、`SalesOrder`、`WorkOrder` 等具体领域类型。

### 4.3 Business Capability Protocol

Business Capability Protocol 是 Agent Platform 与业务应用之间的稳定契约，包含：

- 应用 Manifest 和依赖
- 业务对象描述及跨应用引用
- Tool 输入、输出、错误和版本 Schema
- 领域事件及其版本 Schema
- 权限、数据范围、风险级别和审批要求
- 幂等、并发、超时、重试和补偿语义
- 通用 UI Surface 描述
- Agent 技能和企业知识入口

Agent 从能力注册中心动态发现能力，不在系统 Prompt、前端菜单或编排代码中写死 ERP 工具列表。

### 4.4 企业应用包

每个企业应用包包含：

1. `manifest`：应用标识、版本、依赖和兼容范围。
2. `domain`：业务对象、状态机、规则和领域服务。
3. `capabilities`：Agent 和人工界面可调用的查询与操作能力。
4. `events`：发布与订阅的领域事件。
5. `surfaces`：列表、详情、表单、单据、报表和审批。
6. `policies`：权限、数据范围、风险级别和审批规则。
7. `knowledge`：经版本化发布的术语、SOP、模板和使用说明。

典型应用包：

- CRM：线索、客户、联系人、商机和销售活动。
- ERP：商品、报价、销售订单、采购、履约、质量、出运、业务财务和利润。
- MES：生产订单、工艺路线、工序、派工、报工、设备和质量追溯。
- WMS：仓库、库位、库存、批次、收发货和盘点。
- SRM：供应商准入、询价、绩效和供应商协同。

ERP 通过能力契约依赖 CRM 的客户能力，不复制客户主数据。首期产品发行版同时安装 CRM 基础包与 ERP 套件；未来可单独形成 Agent+CRM 产品组合。

## 5. 部署与模块边界

### 5.1 首期部署形态

- Agent Runtime 独立进程部署。
- Agent Platform 与首期业务应用采用模块化单体。
- PostgreSQL 为事务数据库；同一集群内按平台和应用划分独立 Schema。
- 对象存储保存附件和单据文件。
- 事务 Outbox 发布领域事件。
- 事件总线承载异步通知、跨应用编排和分析投递。
- 搜索与分析读取业务事件构建专用读模型，不反向成为交易事实来源。

### 5.2 拆分条件

只有满足以下任一条件时，才将应用模块拆为独立服务：

- 独立扩缩容带来可测量收益。
- 数据隔离或合规要求必须物理分离。
- 团队所有权已经稳定且接口边界清晰。
- 发布频率冲突已成为持续交付瓶颈。

不得以“未来可能需要”为理由预先拆分微服务。

## 6. 数据所有权与跨应用协作

### 6.1 数据所有权

- 平台拥有租户、组织、用户、Agent 任务、委托授权、策略和审计。
- CRM 拥有客户、联系人、线索和商机。
- ERP 拥有商品、报价、订单、采购、履约、质量、出运、业务财务和利润。
- MES 拥有生产订单、工艺、工序、报工和设备状态。
- 其他应用按照 Manifest 声明自己的业务对象和所有权。

应用之间不得跨 Schema 直接读写。读取通过查询能力或订阅读模型，写入必须调用对象所属应用的命令能力。

### 6.2 企业对象标识

每个对象使用以下全局引用格式：

```text
tenant_id + app_id + object_type + object_id
```

跨应用关系保存在对象关系目录中，包含关系类型、来源、有效期和版本，不复制完整业务对象。

### 6.3 领域事件

事件信封必须包含：

- `event_id`
- `event_type` 和 Schema 版本
- `tenant_id`
- 业务对象全局引用
- `occurred_at`
- `actor` 和 `agent_task_id`
- `correlation_id` 和 `causation_id`
- `idempotency_key`
- 数据分类和可见范围

应用通过事务 Outbox 保证业务提交与事件发布的一致性。消费者通过幂等键、对象版本和因果链处理重复、乱序与回放。

### 6.4 ERP 与 MES 协作示例

1. ERP 发布 `production-demand.created.v1`。
2. MES 订阅事件并创建生产订单。
3. MES 发布排产、缺料、延期和完工事件。
4. 平台编排 Agent 联合分析 ERP 交期与 MES 进度。
5. 调整客户承诺时，Agent 必须调用 ERP 能力，不得直接修改销售订单。

## 7. 能力契约

每项能力至少声明：

- 稳定名称，例如 `erp.sales_order.create`
- 语义版本
- JSON Schema 输入、输出和结构化错误
- 查询或写入属性
- 所需权限与数据范围
- 默认风险级别和允许的策略覆盖范围
- 金额、数量、对象范围和调用频率限制
- 幂等、并发版本、超时和重试规则
- 补偿能力或不可补偿声明
- 成功验证条件
- 数据敏感级别和审计保留期限

破坏性变更必须发布新版本。旧版本在迁移期继续运行，能力注册中心阻止不兼容的 Agent 工作流静默升级。

## 8. Agent 运行模型

### 8.1 Agent 角色

首期采用一个平台编排 Agent 加多个领域技能包：

- 平台编排 Agent：理解目标、拆解计划、选择能力、跟踪任务和处理异常。
- 领域技能包：为 CRM、ERP、MES 等领域提供知识、范例和能力选择指导。
- 事件 Agent：监听领域事件和时间条件，主动启动任务。
- 审批守门员：独立执行风险和授权判断，编排 Agent 无权绕过。
- 结果评估器：依据结构化成功条件验证结果，决定完成、重试、换方案或升级人工处理。

“ERP Agent”“CRM Agent”“MES Agent”是安装相应应用包后形成的领域能力视图，默认共享平台任务、授权和审计体系，不是彼此争夺业务对象的独立运行时。

### 8.2 任务生命周期

```text
目标 → 计划 → 步骤 → 能力调用 → 业务结果 → 验证 → 完成/阻塞/待确认
```

每项任务包含：

- 租户、发起人、责任人和 Agent 身份
- 关联的全局业务对象
- 目标、截止时间和结构化成功条件
- 风险级别、授权范围和预算限制
- 当前计划版本、步骤、重试次数和阻塞原因
- 输入、输出、证据、审批和执行轨迹

### 8.3 记忆边界

- 企业知识：制度、SOP、术语和模板，版本化发布并可回滚。
- 业务事实：每次从业务应用实时读取，不进入模型长期记忆。
- 用户偏好：只保存展示、沟通和工作习惯，不替代权限与业务规则。
- 执行经验：保存有效策略和失败原因，再次使用前重新校验业务条件。

## 9. 自主执行与安全治理

### 9.1 能力调用信封

每次能力调用必须携带：

- 租户、用户和 Agent 身份
- 能力名称、版本、目标对象与数据范围
- 风险级别、金额或数量上限
- 授权来源和有效期
- 预期结果与验证条件
- `idempotency_key`
- 计划版本、证据和因果链

Tool Gateway 依次执行 Schema 校验、身份鉴别、权限判断、数据范围检查、风险策略、业务规则和幂等检查。Agent 无法跳过任一环节。

### 9.2 五级风险模型

| 等级 | 典型动作 | 默认处理 |
|---|---|---|
| R0 查询 | 搜索、分析、预测、生成报告 | 自动 |
| R1 可逆内部动作 | 创建草稿、分配任务、更新非关键字段 | 自动，可撤销 |
| R2 有限业务影响 | 阈值内调整计划、发送常规通知 | 按策略自动，事后通知 |
| R3 重大或不可逆动作 | 合同生效、付款、价格或信用变更、供应商切换、MES 设备控制 | 人工确认 |
| R4 禁止动作 | 越权访问、绕过审批、删除审计、超出授权范围 | 永久拒绝 |

应用包可以提高动作风险等级，不能将平台定义的禁止动作降级。MES 涉及设备和人员安全时，即使没有金额影响，也默认提升到 R3。

### 9.3 人工确认

审批必须展示：

- Agent 拟执行的动作及原因
- 使用的业务事实与数据时间
- 成本、交期、质量、合规和安全影响
- 可选方案与不执行后果
- 将被修改的对象和字段
- 可撤销性及补偿方式

用户确认绑定计划版本和关键事实哈希。关键事实变化后，旧确认立即失效，Agent 必须重新计算并再次申请。

### 9.4 防失控措施

- 外部邮件、附件、网页和自由文本默认是不可信数据，不能改变系统指令或授权。
- 模型参数必须通过 Schema、权限和业务规则校验。
- 连续失败、成本超限、异常重试或结果无法验证时自动停止。
- 租户可配置单次、每日和每类能力预算。
- 所有写操作声明撤销或补偿方式；不可补偿动作自动提高风险。
- 管理员可暂停单个任务、Agent、应用包或整个租户的自主执行。

## 10. 信息架构与交互设计

### 10.1 交互原则

系统以“目标 → Agent 执行 → 人处理例外”为主流程，以“进入模块 → 查找对象 → 人工操作”为完整兜底。Agent 对话不能替代业务对象、凭证和可审计界面。

### 10.2 一级导航

首期 ERP 产品组合提供：

- 总览
- CRM
- 商品
- 销售
- 采购
- 跟单
- 质量
- 出运
- 财务
- 利润
- 数据
- 设置

审批作为全局“待我确认”入口；Agent 中心提供任务、自动化、执行轨迹和能力管理。安装新的业务应用包后，导航根据其 Manifest 和用户权限动态扩展。

### 10.3 主界面结构

参考订单交付监控塔，桌面端固定为四个区域：

1. 左侧窄导航：切换业务域并显示异常、待办数量。
2. Agent 驾驶舱：展示当前目标、计划、执行步骤、已完成动作、阻塞和建议指令。
3. 业务工作区：按上下文打开列表、详情、表单、单据、报表或审批。
4. 全局顶栏：统一搜索、快捷指令、自治状态、通知、租户和用户身份。

业务工作区支持 `hidden`、`peek`、`work`、`full` 四种状态。Agent 只有在用户需要核对、处理异常或确认高风险动作时主动展开工作区。

### 10.4 运行状态

- 观察：Agent 只分析与建议，不写业务数据。
- 协作：R0、R1 自动执行，其余依据策略确认。
- 自主：R0 至 R2 按企业策略执行，R3 仍需确认，R4 永久禁止。

租户设置默认状态，并可按应用、业务域、角色和具体能力覆盖。

## 11. 首期 ERP 与服装外贸范围

首期跑通：

```text
客户需求 → 报价 → 销售订单 → 采购 → 跟单 → 质检 → 出运 → 收付款 → 订单利润
```

核心场景“保证本周订单按期出运”：

1. Agent 查询本周订单、里程碑和依赖。
2. 识别面料延误并评估影响订单与预计损失。
3. 自动联系供应商获取承诺，形成结构化跟进记录。
4. 自动重排低风险内部任务。
5. 生成供应商切换方案，核算成本、毛利和交期。
6. 因涉及供应商变更和成本增加，提交 R3 人工确认。
7. 确认后调用 ERP 能力变更采购安排并通知相关负责人。
8. 持续监控新承诺，直到出运完成或再次升级异常。

## 12. 异常处理与恢复

Agent 错误必须转换为明确、可恢复的业务状态。

- 参数或业务校验失败：不自动重试，解释冲突字段并重新规划。
- 权限或风险拒绝：立即停止，展示缺失授权或审批条件。
- 并发版本冲突：读取最新对象，废弃旧计划后重新计算。
- 外部服务超时：按照能力契约有限重试，超限转人工待办。
- 部分成功：保留已提交结果，执行补偿或生成恢复清单。
- Harness 或模型不可用：业务应用继续支持人工操作，后台任务安全暂停。
- 结果无法验证：不得标记完成，进入“需要复核”。
- 事件重复或乱序：通过幂等键、对象版本和因果链处理。

每个失败任务必须回答：失败步骤、已改变的数据、自动恢复结果、人工下一步。

## 13. 测试与质量策略

### 13.1 测试层级

- 应用包契约测试：Manifest、能力 Schema、事件版本、权限和风险策略。
- 领域测试：各业务应用的状态机、规则、金额和事务一致性。
- Agent 轨迹测试：固定业务快照下的计划、能力选择、停止条件和结果。
- 安全测试：越权、提示注入、恶意附件、审批绕过和跨租户访问。
- 故障测试：模型超时、事件重复、工具失败、网络中断和服务重启。
- 回放测试：使用脱敏真实轨迹回归新模型、Prompt、策略和技能版本。
- UI 测试：导航、驾驶舱、动态工作区、审批、人工接管和人工兜底。
- 跨应用测试：CRM、ERP、MES 等应用包的能力和事件兼容性。

模型输出不以固定文案作为通过条件，而以是否选择合法能力、是否满足业务结果、是否遵守授权边界判断。

### 13.2 发布门槛

- 所有领域和契约测试通过。
- R3、R4 动作无法通过提示、参数或重放绕过。
- 重复调用不产生重复业务结果。
- 关键跨应用事件可安全重复和回放。
- Agent 失败后可以明确恢复，且人工兜底可用。
- 新版本能力契约通过向后兼容检查。
- 参考界面的桌面布局、关键交互和可访问性完成视觉与浏览器验证。

## 14. 首期验收标准

首期交付 Agent Platform、CRM 基础包、ERP 应用套件与服装外贸行业包，并满足：

1. 从客户需求生成报价和销售订单。
2. 自动拆解采购、跟单、质检和出运任务。
3. 主动识别交期风险并执行 R0 至 R2 范围内的授权处置。
4. 对供应商切换、成本增加等 R3 动作申请人工确认。
5. 汇总应收、应付和订单利润。
6. 任一业务结果可追溯到 Agent 计划、能力调用、审批和凭证。
7. 关闭 Agent 后，关键 ERP 功能仍可人工完成。
8. 安装一个示例 MES 应用包时无需修改 Agent Platform 核心。
9. 示例 MES 包可注册至少一个业务对象、一项查询能力、一项写能力、一个领域事件和一个 UI Surface。
10. 替换模型适配器不会改变业务对象、权限或领域事务。

## 15. 建议实施分期

### 阶段 0：架构验证

- DeepSeek Harness 适配层
- 应用 Manifest 与能力注册中心
- Tool Gateway、调用信封、风险策略和审计
- 动态 Surface 协议
- 一个最小 CRM 能力与一个最小 ERP 能力贯通

### 阶段 1：可运营业务闭环

- CRM 基础包与 ERP 模块化业务内核
- 服装外贸行业包
- Agent 驾驶舱、审批和人工兜底界面
- 订单交付风险场景端到端运行

### 阶段 2：平台扩展验证

- 不可用于生产的最小 MES 合约探针
- 跨应用事件和编排
- 应用安装、升级、禁用和兼容性检查
- Agent+CRM 独立产品组合验证

### 阶段 3：生产化

- 多租户商业化与私有化部署
- 可观测性、灾备、安全运营和成本治理
- 脱敏轨迹评估集与发布门禁
- 应用开发者文档、SDK 和认证流程

## 16. 关键设计原则

1. Agent 决定计划，业务应用决定规则与事实。
2. 能力调用是唯一写入通道，模型永远不直连业务数据库。
3. 平台不依赖 ERP，ERP 也不依赖 Harness 私有结构。
4. 应用拥有数据，跨应用通过能力与事件协作。
5. 高自主不等于无控制；所有动作必须在可验证的委托权限内。
6. Agent 失败不能阻断企业基本业务，人工界面始终是完整兜底。
7. 先用模块化单体验证边界，再根据证据拆分服务。
8. 首期同时验证业务价值和平台可扩展性，避免只做一次性的 ERP Agent 演示。
